# Linda Playground slides

把文字编排为可阅读、可操作、可分享的视觉演示。用动态字体、现代主义网格、鲜明色彩和可操作组件形成 Linda Playground slides 的表达语言，让动效解释内容，让密集信息有可进入的深度。

## 先确定本轮范围

- 读取用户文字、现有文件与已确定偏好。沿用已批准的内容、配色、视觉及交互方向。
- 区分制作整站、修改局部、仅手机适配、独立 HTML 导出。用户要求副本时，先创建副本；用户要求只修改手机端时，保留桌面布局与交互。
- 用户只要求方案或结构时，只给文字方案。用户已确认制作时，直接完成，不重复请求确认。
- 默认用中文编排中文材料；保留有意义的英文术语与专名。根据场景选择演讲主导或自主阅读的信息密度。
- 默认采用限定色库中的多彩组合。用户指定选色时按 [visual-system.md](references/visual-system.md) 处理，允许橙色。不要把某次项目的禁色、姓名、页数、日期或二维码固化为通用规则。

## 执行顺序

### 1. 提炼内容并保留依据

阅读 [editorial.md](references/editorial.md)。为每个原文要点安排位置：主画面、点击详情或合并后的表述。

- 主画面保留主题、核心判断、关键数字、金句及易扫读的结构。
- 第二层展示分类、比较、流程、示例和简短解释。
- 详情层保存方法、检查项、异常情况、操作步骤、完整资源名和可点击参考网址。
- 压缩口头阐释与重复表述，保留实际可用的信息。不得杜撰案例、事实、链接或工具能力。
- 把临时的内容映射和场景计划留在工作文件中；无需把这些内部说明写进成品页面。

### 2. 设计场景与节奏

用简短场景表明确每一屏的重点、内容结构、配色、主效果、用户操作与详情入口。按内容需要决定页数。

- 在强视觉场景与安静阅读场景间交替；不要把所有页面都做成同一种卡片墙。
- 并列分类需要比较时，在同一个场景渐进出现，最后整齐地共同可见。
- 为复杂教程提供独立、醒目、可点击的主流程图；进入对应章节后保留轻量次级导航和返回入口。流程节点数量随材料变化。
- 给画面明确的阅读停留状态；不要让长篇文字持续移动。

### 3. 选择字体、配色与艺术效果

阅读 [visual-system.md](references/visual-system.md) 与 [motion-catalog.md](references/motion-catalog.md)。

- 使用原站的 12 个颜色 token；可选中性底色加点缀、双色、多色、全色库。不要添加色库外的紫色、青绿色或灰阶。
- 为 default、hover、focus、active、expanded 分配颜色。检查相邻模块的静态与交互状态，避免相邻色块变成同色；撞色不能牺牲正文可读性。
- 把大字号、字重、字宽、紧密排版、字阵、几何结构视为主要视觉材料。仅对字体真实支持的轴做可变字体动画。
- 主动从文字、组件、转场三类效果中组合；较长内容至少尝试三类的不同机制，随后按语义与性能删减。不要为了凑数量重复或添加无意义动效。
- 每个视口通常保留一个主导动效与一到两个轻量反馈。把丰富性分配到整段叙事。
- 从附带组件选取基础机制，再为当前内容改造。不要直接交付演示模板或强迫每次都用同样的版式。

### 4. 实现网页与可操作内容

读取 [implementation.md](references/implementation.md)，使用原生 HTML/CSS/JS 作为轻量起点；已有项目则沿用它的技术栈。

```bash
python <skill-root>/scripts/scaffold.py /absolute/output/project
```

替换示例文字、场景和详情；删除不用的组件。附带运行时支持可变字体控制、距离字阵、3D 标签环、错位文字揭示、速度形变、折叠与磁吸反馈、几何旋转、流程导航、网格渐显、模拟对话和原生详情窗。

- 使用实际 button、a、input、dialog；给可点击区域可见的操作暗示与键盘焦点。
- UI 型场景允许用户修改一个输入并立即看到变化。模拟对话、进度或部署要标注演示；用户数据不应被静默发送到外部服务。
- 不把关键内容藏在纯 hover、长按或不断变化的随机状态里。
- 保留语义正文；逐字动画的装饰副本对辅助技术隐藏。

### 5. 分别处理布局、导航与运动

阅读 [responsive-and-navigation.md](references/responsive-and-navigation.md)。

- 根据可用宽度和高度重新分配网格、字号、间距和模块位置；不要整体缩放固定画布来适配。
- 让页面充分使用空间，同时保留有意的留白。必要时把详细内容移入详情层，不以微小字体强塞一屏。
- 使用一致的阅读锚点。桌面演示可吸附到场景边界；手机和长内容采用自然滚动或温和吸附，保证上下文与手势正常。
- 内部动画结束后要有稳定停留；不得因章节实现方式不同而丢失某几页的吸附行为。
- 支持触控、键盘、减少动态效果、屏幕缩放、手机安全区与动态视口。只在可见区域运行动画。

### 6. 打包并验证成品

```bash
python <skill-root>/scripts/bundle.py /absolute/output/project/index.html --out /absolute/output/interactive.html
python <skill-root>/scripts/audit.py /absolute/output/interactive.html
```

打包工具会对使用附带字体的项目重新生成中文子集、内嵌本地样式/经典脚本/字体/图片，并保留字体许可。实际生成后必须检查最终 HTML 本身；静态检查不等于浏览器验收。

- 核对正文及详情是否覆盖原文重要信息，所有资源入口是否存在，流程节点是否到达正确位置。
- 至少验证常见桌面宽屏、较矮的笔记本屏幕、窄手机、宽手机和手机横屏。检查完整阅读路径、首尾场景和最密集的页面。
- 检查滚动吸附、返回位置、详情关闭、键盘、触控替代、相邻颜色及字形覆盖。
- 单文件交付应在断网打开后保留字体、效果、内容和本地交互。显式点击的参考网站允许联网。
- 当前环境无法完成某项实测时，说明验证限制；不要声称已验证不存在的浏览器结果。
- 按当前环境的文件保存规则交付 HTML。只有用户要求发布网址时，才使用相应网站发布流程。

## 完成标准

让读者在每个场景迅速看见重点、停下来读完、主动进入详细内容，再回到叙事。保证色库一致、字体有表现力、组件有反馈、场景有变化。把文字编排质量、空间使用、交互可达性和独立可分享性一起作为验收标准。
